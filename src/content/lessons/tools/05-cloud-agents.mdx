云端 Agent 通常会把仓库克隆到临时环境，安装依赖，修改代码并运行检查，最后以 Diff 或 Pull Request 交付。你可以关闭电脑，任务仍继续运行。

## 它解决了什么

- 耗时构建不占用本地电脑；
- 多个独立任务可以并行；
- 执行环境易于重建；
- 结果自然进入 Pull Request 审查；
- 适合 Issue 明确、测试完善的仓库。

## “在沙箱里”不等于“数据没有出网”

沙箱主要限制任务对宿主系统的影响。代码、依赖、日志和提示仍可能被上传到服务提供方。企业需要分别确认：

1. 哪些仓库允许接入；
2. 模型和执行环境位于哪里；
3. 日志保留多久；
4. Secrets 如何注入、能否被打印；
5. 生成的 Pull Request 触发哪些 CI 权限。

<Callout type="enterprise" title="适合云端的任务">
  优先选择边界清楚、自动测试完整、无生产凭证、可以通过 Pull Request 审查的任务。探索性需求或包含敏感数据的项目先留在受控本地环境。
</Callout>

## 并行不是把一个模糊任务复制五份

好的并行任务之间拥有清晰文件或接口边界，例如：

- Agent A 补测试；
- Agent B 更新文档；
- Agent C 在独立 worktree 实现 UI；
- 人类最后检查接口是否一致。

如果多个 Agent 同时改同一套核心文件，合并成本可能高于节省的时间。
