“代码看起来正确”“类型上应该没问题”“我已经修复”都不是证据。证据来自独立观察。

## 四层验证

| 层级 | 证明什么 | 示例 |
| --- | --- | --- |
| 静态 | 结构、类型、格式基本有效 | TypeScript、Astro check |
| 单元 | 独立逻辑符合输入输出 | URL 拼接、进度存储 |
| 集成 | 多个部分能一起工作 | 构建、搜索索引生成 |
| 用户路径 | 真实浏览器能完成目标 | 搜索、导航、勾选进度 |

高风险功能还需要安全、性能和人工业务验收。

## 把形容词变成观察

- “响应式” → 375px 与 1280px 无横向滚动；
- “搜索可用” → 输入“API Key”能返回配置课并正确跳转；
- “部署成功” → 无痕窗口访问生产深层 URL 返回 200；
- “安全保存” → 仓库扫描不含 Key，进度只写入 localStorage；
- “无障碍” → 键盘可访问全部交互，焦点可见。

## 要求 Agent 报告真实结果

```text
完成后请报告：
1. 实际运行的命令；
2. 每条命令的退出状态与关键输出；
3. 没有运行的检查及原因；
4. 仍需要人工验证的项目。
不要把建议运行的检查写成已经通过。
```

<Callout type="warning" title="测试通过不等于需求正确">
  测试只能证明它覆盖的断言。若需求理解错了，完整通过的测试可能只是稳定地证明错误行为。业务验收标准必须由人确认。
</Callout>

## 失败是有价值的证据

验证失败时，保留原始错误和触发步骤。不要立即让 Agent 大面积重写；先判断失败属于环境、配置、数据还是代码，再选择最小修复。
