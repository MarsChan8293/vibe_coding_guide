测试不是请 Agent 再看一遍自己的答案。测试是让独立工具、浏览器和人类观察结果，并留下可复查证据。

## 第一层：静态构建

```bash
npm run build
```

退出码必须为 0。警告也要阅读：废弃 API、缺失资源或无效 HTML 可能暂时不阻止构建，却会在更新后失败。

## 第二层：内容核对

对照 `CONTENT.md`：

- 姓名、链接与联系方式正确；
- 没有 Lorem ipsum 或示例文本；
- 没有虚构项目、结果或客户；
- 外部链接打开到预期页面；
- 页面标题和描述适合公开分享。

可以让 Agent 搜索占位符，但由你判断结果：

```text
只读检查整个仓库，搜索 TODO、FIXME、example、placeholder、
lorem、localhost、replace-me 和可能的密钥格式。
按文件与行号报告，不要修改。
```

## 第三层：浏览器行为

在生产构建预览，而不是只看开发服务器：

```bash
npm run preview
```

检查：

- 直接刷新深层 URL 不会 404；
- 图片、CSS 和字体都能加载；
- 手机与桌面布局正常；
- 键盘可用；
- 控制台没有错误；
- 关闭网络后，已加载页面不依赖外部 CDN。

## 第四层：Git 审查

```bash
git status
git diff --stat HEAD~1
git diff HEAD~1
```

如果多个提交组成完整功能，可把基线提交替换为对应哈希。关注：

- 意外修改或删除；
- 新依赖是否必要；
- 构建产物是否被误提交；
- 是否出现密钥、内部地址和个人信息；
- CSS 是否用大量覆盖掩盖结构问题。

<Callout type="warning" title="不要让同一个 Agent 自证正确">
  Agent 可以帮助列检查项和定位问题，但最终判断应来自构建工具、浏览器、Git Diff 与你的业务事实。
</Callout>

## 写下已知限制

在 README 中加入“已知限制”：

- 首版没有博客；
- 没有表单后端，联系使用邮件链接；
- 只支持现代浏览器；
- 内容更新需重新构建发布。

诚实的限制比虚假的“全部完成”更专业。
