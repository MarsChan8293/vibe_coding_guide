模型只能根据当前上下文做判断。上下文包括你的指令、项目规则、读取的文件、工具输出和之前的对话。它不是“整个项目自动进入模型脑中”。

## 高价值上下文的四层

1. **目标**：最终要改变什么用户结果；
2. **约束**：不能碰什么、必须兼容什么；
3. **相关事实**：接口、组件、错误日志和现有测试；
4. **验收证据**：完成后运行什么、观察什么。

示例：

```text
目标：修复搜索结果在 GitHub Pages 子路径下跳转错误。
约束：不更换 Pagefind，不修改内容路由。
事实：生产 base 为 /vibe_coding_guide/；本地根路径正常。
相关文件：搜索组件、Astro 配置、现有 E2E 测试。
验收：点击搜索结果进入正确深层 URL，构建与 E2E 均通过。
```

## 低价值上下文

- 与任务无关的整段聊天记录；
- 没有说明用途的几十个文件；
- 重复粘贴的完整构建日志；
- 相互冲突且没有优先级的规则；
- “请用最佳实践”这类无法观察的要求。

<Callout type="note" title="先让 Agent 找，再确认它读">
  对中型仓库，与其把所有文件塞进去，不如先让 Agent 搜索候选文件、说明关联，再授权它读取最相关部分。
</Callout>

## 长会话什么时候该结束

出现这些信号时，新开会话并写一段交接：

- Agent 反复忘记已经确认的边界；
- 同一个错误被用不同方式重复修；
- 对话中包含多个已经结束的任务；
- 计划与当前文件状态明显不一致。

交接只保留当前事实：

```text
已完成：...
当前 Git 状态：...
仍失败：...
已验证不是：...
下一步只需要：...
```
