传统聊天机器人回答错误，影响通常停留在文本；Coding Agent 回答错误后还可能修改文件、执行脚本、安装依赖、连接网络或提交代码。

## 五个主要风险面

### 凭证

Key、Token、SSH 密钥和云凭证可能通过配置、日志、截图或 Git 泄露。使用环境变量或企业 Secret 系统，发现泄露立即轮换。

### Prompt Injection

Agent 读取网页、Issue、README 或依赖文档时，可能遇到诱导它忽略规则、下载程序或泄露数据的指令。外部内容是数据，不是自动可信的命令。

### 软件供应链

模型可能生成名字相似但不存在或恶意的包。安装前检查官方来源、维护状态、锁文件变化和许可证。

### 过度权限

工作区写权限、系统写权限和无限网络不是同一级别。默认最小权限，对删除、发布、消息发送和生产操作显式审批。

### 虚假完成

Agent 可能跳过检查、误读输出或用“应该”代替实际运行。要求命令、退出状态、Diff 和人工验收。

<Callout type="warning" title="长期 Agent 的风险会累积">
  OpenClaw、自动化任务和多 Agent 系统运行更久、连接更多服务。一次低概率错误在持续运行中会变成高概率事件，因此需要配额、日志、停止开关和定期复核。
</Callout>

## 一个可执行的团队基线

- 批准的工具、Provider 与版本；
- 允许和禁止处理的数据类型；
- 默认文件、命令和网络权限；
- 社区 Skill、插件与 MCP 的审计流程；
- 代码合并与发布的人工门槛；
- 凭证泄露、异常命令和数据事件的响应人；
- 工具更新后的回归试点。

## 复盘不是写心得

每个重要任务结束后回答：

1. 哪一段上下文真正帮助了 Agent？
2. 哪个假设导致返工？
3. 哪项检查最早发现问题？
4. 哪个步骤可以自动化，哪个必须保留人工判断？
5. 下次应该新增规则、测试、模板还是 Skill？

只把重复出现、已经验证有效的方法沉淀为规则。一次偶然成功不要立刻变成全局指令。

## 最后的工作循环

> 说清目标 → 划定边界 → 审查计划 → 小步实现 → 独立验证 → 人工验收 → 复盘沉淀。

这套循环不会让 Agent 永远正确。它让错误更早出现、更容易理解、更容易回退，也让速度真正转化为可交付价值。
