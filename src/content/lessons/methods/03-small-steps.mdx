Agent 能在几分钟内改几十个文件，不代表你应该允许它这么做。生成速度越快，审查带宽越容易成为真正瓶颈。

## 一次理想迭代

- 解决一个可命名的问题；
- 修改一组高度相关的文件；
- 不同时引入多个新概念；
- 能运行一组明确检查；
- Diff 可以在十分钟内由人读完；
- 失败时能整体撤销。

## 三种拆分方式

### 按行为

先让搜索结果路径正确，再优化搜索样式。行为与视觉分开验证。

### 按层

先定义数据或类型，再实现逻辑，最后接 UI。每层有自己的测试。

### 按风险

先做只读分析和测试，再修改代码；配置迁移、删除和权限变化单独处理。

<Callout type="note" title="提交说明应该描述意图">
  `Fix search links under GitHub Pages base path` 比 `Update files` 更容易回顾。提交是给未来的人和 Agent 留下的上下文。
</Callout>

## 不要为了小而制造半成品

小步仍必须在自己的边界内完整。例如新增一个按钮，至少包含可访问名称、点击行为和测试；不能只提交一个没有行为的视觉外壳并声称功能完成。
