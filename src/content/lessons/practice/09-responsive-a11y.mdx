“加了媒体查询”不能证明响应式；“用了语义标签”也不能证明键盘可用。你需要实际走一遍页面。

## 两个视口，四项观察

在浏览器开发者工具中至少检查：

- 375 × 812：常见窄屏手机；
- 1280 × 800：常见桌面窗口。

逐项观察：

1. 页面是否出现非预期横向滚动；
2. 标题是否挤压、遮挡或变成单字一行；
3. 导航和链接的点击区域是否足够；
4. 项目内容顺序是否仍然合理。

不要只截首页第一屏。滚到页面底部，检查项目卡片、长链接和联系方式。

## 只用键盘完成一次浏览

刷新页面后不要碰鼠标：

1. 按 `Tab`，焦点应该清楚可见；
2. 能跳过重复导航或很快进入正文；
3. 所有链接和按钮都能访问；
4. 焦点顺序与视觉顺序一致；
5. 按 Enter 能激活链接。

如果导航只能靠鼠标悬停打开，它还没有完成。

## 让 Agent 修复具体失败

差的指令：

```text
优化移动端和无障碍。
```

可验证的指令：

```text
在 375px 视口，项目标题导致页面横向滚动。
只修改相关布局样式；不要改变内容和桌面排版。
验收：document.documentElement.scrollWidth 等于 clientWidth，
且项目链接保持可见焦点。修改后运行 npm run build。
```

<Callout type="note" title="动画是增强，不是门槛">
  为 `prefers-reduced-motion: reduce` 关闭大幅位移和循环动画。没有动画时，内容顺序和状态仍必须清楚。
</Callout>

## 检查文档结构

- 页面只有一个主要 `h1`；
- 标题按层级排列，不为视觉跳级；
- 图片拥有描述用途的 `alt`，装饰图使用空 `alt`；
- 链接文字能单独说明去向；
- 颜色不是表达状态的唯一方式；
- 正文与背景有足够对比。
